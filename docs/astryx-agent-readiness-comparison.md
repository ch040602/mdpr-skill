# Astryx Agent-Readiness Comparison

Reference snapshot: `facebook/astryx@88a690b4ea7cbdb1916615c6d922879a8e77fb25`.

Astryx is useful as a process reference because it treats CLI commands,
component conventions, theme ownership, docs, and measurement as one shared
surface for people and agents. mdpr-skill should borrow that operating model,
not the React or StyleX implementation details.

## Borrowed Patterns

- Branch-local CLI docs: agents should query the checkout they are editing
  instead of relying on stale prompt memory.
- Dense topic output: a short `--dense` view gives enough context to act
  without flooding the model.
- Human/agent parity: the same CLI command should be useful to a maintainer and
  an automated agent.
- Ownership transfer: proposals can be generated by a helper, but the owning
  runtime or user must approve and bind them.
- Measurement discipline: improvement claims should be backed by tests,
  rendered evidence, schema checks, or eval gates.

## MDPR Mapping

| Astryx pattern | mdpr-skill equivalent |
| --- | --- |
| `docs --dense` | `mdpr-skill docs <topic> --dense` |
| component/template discovery | command and workflow discovery |
| theme custom property ownership | approval-bound theme candidate plus MDPR-owned theme binding |
| swizzle/eject ownership transfer | change request, override candidate, or theme candidate awaiting approval |
| vibe tests | eval-core, rendered preview review, schema sync, and MDPR manifest gates |

## Non-Goals

mdpr-skill must not import Astryx React component APIs, StyleX internals,
frontend layout prescriptions, or source-ejection mechanics as PPT renderer
behavior. MDPR remains responsible for final slide geometry, typography,
theme colors, assets, z-order, and editable PPTX objects.

## Added Surface

The `mdpr-skill docs` command now exposes branch-local agent guidance:

```bash
mdpr-skill docs --list
mdpr-skill docs bootstrap --dense
mdpr-skill docs boundaries --dense
mdpr-skill docs template-fill --dense
mdpr-skill docs media --dense
mdpr-skill docs review --dense
mdpr-skill docs design-import --dense
mdpr-skill docs astryx-comparison --dense
```

This gives agents the same current command and boundary context that
maintainers see, while preserving MDPR as the deterministic runtime.
